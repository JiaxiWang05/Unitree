A

支架：一步一步装

左边是用真实模型做的 3D 示意：机器人胸口来自 Unitree 官方模型，紫色支架就是你打印的这个文件。可以拖动旋转、双指缩放。橙色点标出每一步要看的地方。

拖动旋转 · 滚轮或双指缩放

为什么设计成这样

每一个形状都对应一个约束。点按钮会在 3D 里跳到相关的那一步。

装在胸口，不装在头上

头部"脸"上的窗口是机器人自带深度相机（D435i）的视野。程序靠它看地面上的站位区域，摄像头放那里会把它挡住。

深度相机看站位区域的视线离支架最近 15 mm

用胸口下面两个 M6 孔

这是 Unitree 官方的配件安装孔，金属螺纹、表面平。两个圆垫块按胸口的局部角度做（前倾约 5°，每个孔往外偏约 6°），所以能同时贴平，其它地方都不碰胸口。

孔距 64.5 mm · 垫块外的部分离胸口 ≥ 3.3 mm

拔掉夹子，一颗螺丝从下面固定

夹子是给显示器用的，可以晃。相机底面本来就有一个 ¼" 标准三脚架螺纹孔（被夹子挡着），拔掉夹子后直接拧在支架上最稳，颜色和距离判断也更稳定。

螺纹孔中心离相机背面约 14.5 mm

往上仰 20°

镜头离地约 0.98 m，访客的脸在 1.5–1.8 m。平着放的话，人一走近头就出画面了。仰 20° 后，1.6 m 高的脸在 0.76 m 外就进画面；3–5 m 外的人从大腿往上也看得到。

视野上沿高于水平 46° · 下沿低于水平 6°

椭圆槽，螺丝只伸进 4 mm

螺纹孔的位置来自拆机照片和别人做的支架，不是 Logitech 公布的，所以开成可前后各让 3 mm 的槽。螺纹是一片用双面胶贴在里面的薄钢片，螺丝太长会把它顶掉：10.3 mm 塑料 + 1.6 mm 垫圈 + 5/8" 螺丝，正好伸进去 4 mm，约三圈。

可接受的螺纹位置：离背面 11.5–17.5 mm

后挡块留缺口，托板中间开通道

Brio 的 USB-C 口在背面靠下（离底面约 7 mm），你买的线是直插头，约 35 mm 长、比较硬。缺口让插头过去，通道让插头往下伸、线再往上弯。托板因此做得低而长，同时还要躲开深度相机的视线。

插头离支架 3.5 mm · 线可以按约 24 mm 半径往上弯
B

测机器人自带的麦克风（不需要摄像头）

目的：在买别的麦克风之前，先确认自带的 4 麦克风阵列在嘈杂环境里够不够用。这一步只用到机器人和你的电脑。

  1. 机器人开机，放在安全的位置

    不用让它站起来，挂在架子上或坐着都行。遥控器拿在手上。

    为什么：录音只需要语音服务在运行，站立没必要，还多一分风险。

  2. 把语音助手切到 wake-up 模式

    遥控器同时按 L1 + L2，或者在 Unitree app 里：Device → Data → Audio → Voice assistant。在 app 里确认确实是 wake-up 模式。

    为什么：只有这个模式下，麦克风才会把降噪后的声音发到机器人内部网络（组播地址 239.168.123.161:5555）。其它模式下收到的是空的或全是零。

  3. 在 app 里关掉 chat_go

    Device → Service Status → chat_go 关闭。

    为什么：不然有人说 "Hello Robot" 时，Unitree 自带的语音助手会抢着回答，和我们的程序打架。

  4. 电脑用网线连机器人

    网线插到后颈面板的网口。电脑的有线网卡手动设成 IP 192.168.123.99，子网掩码 255.255.255.0（Mac：系统设置 → 网络 → 有线网卡 → 详细信息 → TCP/IP → 手动）。然后试一下能不能连上机器人的 Jetson：

    ping -c 3 192.168.123.164

    为什么：我们的程序跑在机器人的 Jetson（PC2，地址 192.168.123.164）上，麦克风的声音也只在机器人内部网络里传。

  5. 把录音脚本放到机器人上，录 5 秒

    在电脑上下载项目（只要一次），把录音脚本拷过去，然后运行。脚本运行的 5 秒里，在机器人正前方约 1 m 处正常说话。第一次 ssh 会问机器人的密码。

    git clone https://github.com/JiaxiWang05/Unitree && cd Unitree
    scp scripts/record_mic.py unitree@192.168.123.164:~/
    ssh unitree@192.168.123.164 'python3 record_mic.py'
    scp unitree@192.168.123.164:~/mic_test.wav .

    为什么：这个脚本只用 Python 自带的库，Jetson 上不用装任何东西就能跑。最后一条把录音拷回电脑，你可以直接听。

  6. 看脚本说了什么

    No audio at all…一点声音都没收到：多半是没切到 wake-up 模式，回到第 2 步。 All zeros: the mic is muted…收到了但全是零：麦克风被静音了，也是模式不对。 Audio stopped after X s录到一半断了：记下来告诉我。 got N bytes, loudest sample X有声音。5 秒完整的话 N 约 160000。去听 mic_test.wav。

  7. 换几种情况多录几次

    正前方 1 m 正常音量；2 m；站在侧面；用手机放一段嘈杂的人声背景再说话（模拟开放日的大厅）。每次录完都听一下。

    为什么：开放日大厅很吵。如果 1–1.5 m 内都听不清，就该买 ReSpeaker USB 麦克风阵列（约 £58）。听得清就不用花这个钱。

C

配置机器人的电脑，装上软件

需要密码和 sudo 的那两步只能你来做。之后只要这台 Mac 用网线连着机器人，剩下的我在这边远程完成。

你做（只做一次）

  1. 设置免密登录

    ssh-copy-id unitree@192.168.123.164

    为什么：输入一次机器人密码，之后我部署和自检时就不用再问你密码。

  2. 运行配置脚本

    在 Unitree 文件夹里运行。它会问 sudo 密码、机器人要连的 Wi-Fi 名和密码、OpenAI API key（输入时屏幕上不显示）。

    ssh -t unitree@192.168.123.164 'sudo bash -s' < scripts/setup-jetson.sh

    为什么：装系统包、深度相机的权限规则、联网都需要 sudo。key 只存在机器人上的配置文件里，不会写进代码，也不会经过我。

  3. 告诉我"Jetson 配好了"

我做（这台 Mac 连着机器人时）

  1. 部署

    运行 scripts/deploy.sh：拷代码；建 Python 环境；装 CUDA 版 torch、YOLO、Unitree SDK；下载 YOLO 模型并转成 TensorRT（这一步约 5 分钟）；找到 USB 摄像头；生成约 15 段备用语音；设置开机自启。

    为什么：这些都不需要 sudo，可以重复跑，出问题我在这边直接看日志。

  2. 自检

    .venv/bin/python -m greeter --check --check-sound

    为什么：一次检查网络、API key、摄像头、YOLO 速度、深度相机、SDK、麦克风音量，最后用胸口喇叭说一句话，你听到就说明放音也通了。

D

用实验室的 USB 摄像头跑一遍全流程

可以先用实验室的摄像头。程序支持任何标准 USB 摄像头：自动跳过头部的深度相机，用第一个找到的 USB 摄像头，要 640×480 MJPG；曝光、白平衡、对焦能锁就锁，锁不了就保持自动。

下面的命令都在机器人的 Jetson 上运行：先 ssh unitree@192.168.123.164，再 cd ~/g1-greeter。

绝对不要插 XT30 电源口（58 V、24 V、12 V）。摄像头和麦克风只插后颈面板的 USB-C 口（5 V）。

  1. 用转接头接到机器人

    USB-C 公转 USB-A 母，要能传数据的（OTG），不是只能充电的那种。插到后颈面板空着的 USB-C 口（6–8 号口；有一个已经被深度相机占了）。

    为什么：这几个口是 USB 3.0、5 V 1.5 A，摄像头用电很少，够用。

  2. 临时固定在胸口

    用胶带或夹子固定在支架将来的位置附近，朝前、稍微往上仰一点。别挡住脸上深度相机的窗口，也别盖住脖子前面那 4 个麦克风小孔。

    为什么：位置和角度接近 Brio 装好后的样子，测出来的距离和画面才有参考价值。

  3. 看它支不支持 640×480 MJPG

    v4l2-ctl --list-devices
v4l2-ctl -d /dev/v4l/by-id/<摄像头>-video-index0 --list-formats-ext

    为什么：程序要 640×480 MJPG、30 帧。只有 YUYV 也能跑，但帧率可能低。视角比 Brio（90°）窄的话，人要站远一点脸才进画面。

  4. 在地上贴出站位区域

    机器人正前方 0.6–1.4 m、左右各 0.6 m，用胶带贴一个框。再在 1 m、2 m、3 m 处各贴一个记号，用来校准距离。

    为什么：站位区域由头上的深度相机判断：有人站上去说话，就直接开始对话。用平贴的胶带，不要拉绳子，绳子会被当成"有东西"。

  5. 先用固定台词模式跑（不花 API 的钱）

    systemctl --user stop g1-greeter
.venv/bin/python -m greeter --scripted

    测试的人穿绿色衣服，走到 1.5–2 m、面朝机器人：灯变浅绿 → 机器人邀请 → 站到站位区域或回一句话 → 开始对话。

    为什么：先确认看人、灯、喇叭、麦克风、状态切换都通，再接真实的模型。现在的版本只主动邀请穿绿色的人（见下面"待定"）。

  6. 再用真实对话跑

    systemctl --user start g1-greeter
journalctl --user -u g1-greeter -f

    为什么：服务会用 OpenAI 实时语音模型。日志里能看到状态变化、双方说了什么、花了多少钱。哪里不顺告诉我，我来调阈值。

  7. 换成 Brio 时告诉我

    安装时会把找到的摄像头路径写进配置。换成 Brio 后，我要把配置改成新摄像头，再让它重新锁定颜色和曝光。

E

头盔试装件：挂在肩上的两个吊环上

以后 Brio 可以放到头顶：一个弓形架从左肩的吊环翻过头顶，接到右肩的吊环。先只打印弓形架两端的"脚"，挂上去试一下、量几个数，再按实测的数画完整的弓形架。

为什么先打试装件

吊环的形状只来自 Unitree 的 3D 模型。真机的吊环厚度、孔的大小、两个环的距离都可能不一样。完整的弓形架约 15 × 18 cm，打印要很久；这两个小件很快就能打出来，先回答这些问题。

每个约 15 cm³ · PLA 就行

为什么用 M5 不用 M6

螺丝要尽量靠吊环孔的上面，螺母槽才能留在脚的底面以上。用 M6 的话，螺母槽会从底面破出来，螺母离脖子旁边的外壳只有 1.3 mm。M5 螺丝离孔的圆顶还有 1.3 mm。

螺丝 1.33 mm 离孔顶 · 外壳 ≥ 2.2 mm

代价

弓形架的两条腿正好经过头部左右两侧，各挡住头里激光雷达约 10° 的视野。现在的程序不用激光雷达，以后要它自己走、自己避障就要靠它。另外，戴着它不能用吊环把机器人吊起来。

激光雷达每侧约 9.6°

  1. 打印

    打印 hardware/helmet_ring_mount/trial_feet_plate.stl：两个一起，脚的底面贴打印板、小柱子朝上。不用支撑。0.2 mm 层高，3–4 圈墙，30% 填充。

    为什么：槽顶是拱形，螺丝孔 5.5 mm，螺母槽是尖角朝上的六边形，这样都能直接打，不用支撑。

  2. 机器人不要挂在吊环上

    坐着或躺着、关机都行。

    为什么：这两个环本来是吊机器人用的。挂着的时候钩子占着环，也不安全。

  3. 分清左右和前后

    两个是镜像的：外侧面刻着 L 或 R，L 装左肩、R 装右肩；旁边刻的箭头朝前（机器人面朝的方向），六角螺母槽朝脖子那一侧。

  4. 从上往下套到吊环上

    直着往下套，直到螺丝孔对上吊环的孔。

    为什么：槽比模型里的吊环每边宽 1.2–1.6 mm，槽口还有倒角，应该能顺着套进去，不用用力。

  5. 穿螺丝、放螺母

    M5×20 螺丝套一个 M5 垫圈，从肩膀外侧穿进去（螺丝头陷进外侧的沉孔里）：外侧板 → 吊环的孔 → 内侧板。从脖子那一侧把尼龙防松螺母放进六角槽，拧到刚好带住就停。不要拧紧，脚应该还能稍微动一点。

    为什么：以后完整的弓形架靠头顶承重，螺丝只防它掉下来；拧紧会把两块侧板往里夹。

  6. 检查

    能不用力套上、取下；螺丝不用硬塞就能穿过，脚上下还有一点活动量；侧板底下和肩膀之间能塞进一张纸；小柱子竖直、在头旁边、不碰头。

电脑怎么用网线接机器人（只要一次）

网线只在第一次配置时用。配好以后机器人连随身路由器的 Wi-Fi，你的电脑也连同一个 Wi-Fi，我就能用 Wi-Fi 部署和看日志。

推荐：实验室的 Ubuntu 电脑，不用买东西

  1. 网线一头插电脑，一头插机器人后颈的网口

  2. 把有线网卡设成手动地址

    设置 → 网络 → 有线 → 齿轮 → IPv4 → 手动。地址 192.168.123.99，子网掩码 255.255.255.0，网关留空 → 应用。然后把有线关掉再打开。

    为什么：机器人内部网络是 192.168.123.x，没有自动分配地址，电脑要自己占一个不冲突的地址。

  3. 试一下能不能连上

如果要让机器人在室内走动

电脑不用一直在旁边

程序全部跑在机器人身体里的 Jetson 上，开机自动启动；上网靠随身路由器的 Wi-Fi。把路由器绑在机器人背上，Wi-Fi 就跟着它走。网线只在第一次配置时用，走路时绝不能拖着线。

现在的程序按"站着不动"写

程序里没有任何走路指令。机器人一走，画面里所有人看起来都在动，"路过的人不叫"和"一伙人"这两个判断会失灵；"站到对话点上"也要改成"过来聊聊"。

建议：有人拿遥控器带它走

用 Unitree 自带的走路模式，走到人多的地方停下来；程序只在它站定时找人聊天。要改的：走路时暂停找人，改邀请词和提示词里"今天不能动"那句。

安全

G1 约 35 kg，撞到人或摔倒都可能伤人。拿遥控器的人全程跟着，随时能让它停下。风险评估或伦理申请里如果写了"机器人不动"，要先改。让它自己在人群里走（导航、避障）是另一个大项目，开放日前做不完。

待定：任何颜色的衣服都能触发邀请

现在机器人只主动邀请穿绿色的人（站位区域谁都能用）。你说想改成穿什么颜色都行。方案是加一个设置 --invite anyone|green，默认 anyone：开场白改成点名对方身上的一件衣物和颜色，备用语音改成 "Hey there! Come and say hi!"，提示词和收尾句不再提绿色，保留 --invite green 作为选项。还没开始改代码，等你确认。
