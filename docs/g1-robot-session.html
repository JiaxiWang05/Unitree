准备

10 分钟

  1. 从工作人员那里拿到 U 盘和机器人的账号密码

    你

    U 盘是机器人系统的备份，收好就行，今天用不到。账号一般是 unitree。

    密码只在终端提示时自己输入。不要发给我，也不要写进任何文件或 GitHub。

  2. 把这些东西带到机器人旁边

    你
    • 实验室的 Ubuntu 电脑（要有网口）和一根网线
    • 你的 Mac（我在上面操作），和 Ubuntu 电脑连同一个 Wi-Fi
    • 随身路由器：开机，记下 Wi-Fi 名和密码
    • OpenAI API key（脚本里会隐藏输入）
    • 机器人遥控器，电池充满
    • 地面胶带和卷尺
    • 摄像头：Brio 装在支架上，或者先用实验室的 USB 摄像头
    • 再找一两个同学，测"两个人同时说话"要用

  3. 机器人通电，坐着或挂在吊架上

    你

    前面三段不需要它站起来。摄像头插到脖子后面面板的 USB-C 口。

1

接网线、跑设置脚本

20–40 分钟 · 只做这一次

  1. 网线一头插 Ubuntu 电脑，一头插机器人背后的网口

    你

  2. 把 Ubuntu 的有线网卡设成手动地址

    你
    Ubuntu 终端
    ping -c 3 192.168.123.164

    应该看到：3 packets transmitted, 3 received。没有回应的话，检查网线和刚才填的地址。

  3. 在 Ubuntu 上下载项目代码

    你
    Ubuntu 终端
    git clone https://github.com/JiaxiWang05/Unitree.git
cd Unitree

    为什么：设置脚本 scripts/setup-jetson.sh 在这个项目里，要从电脑上发给机器人运行。

  4. 让这台电脑以后登录机器人不用再输密码

    你
    Ubuntu 终端
    ssh-copy-id unitree@192.168.123.164

    它会问一次机器人的密码，你自己输入（输入时屏幕上不显示字）。

    如果提示 no identities found，先运行 ssh-keygen -t ed25519，连按三次回车，再运行上面这条。

  5. 运行设置脚本

    你
    Ubuntu 终端，在 Unitree 文件夹里
    scp scripts/setup-jetson.sh unitree@192.168.123.164:~ && ssh -t unitree@192.168.123.164 'sudo bash ~/setup-jetson.sh'

    提示 still no internet 的话：检查路由器有没有信号、Wi-Fi 名和密码对不对，然后重新运行同一条命令。重复运行不会出问题。

  6. 把最后一行发给我，再让我的 Mac 也能登录

    你

    把 tell Claude: the robot is ready at unitree@… 这一行复制给我。然后把你的 Mac 连到同一个路由器的 Wi-Fi，在 Mac 的终端里运行一次（同样会问一次机器人密码）：

    Mac 终端
    ssh-copy-id unitree@<脚本给出的 Wi-Fi 地址>

    为什么：刚才只给 Ubuntu 电脑开了免密登录。我是在你的 Mac 上操作的，Mac 也要能登录机器人。

2

我来安装（你同时贴地面胶带）

约 20 分钟

  1. 我部署程序、跑自检、启动服务

    Claude

    我在你的 Mac 上运行 scripts/deploy.sh，它会在机器人上：建 Python 环境，装好 CUDA 版的 torch、YOLO、CycloneDDS 和 Unitree SDK，下载人体姿态模型并转成 TensorRT（这一步约 5 分钟），找到胸前摄像头，生成十几句备用语音（包括新的 "Hey there! Come and say hi!"），跑一遍自检，再把服务设成开机自动启动。

    这段时间你不用盯着，做下面两件事就行。

  2. 在地上贴出站位区域和距离记号

    你

  3. 把语音助手切到 wake-up 模式，关掉 chat_go

    你

    遥控器同时按 L1 + L2，或者在 Unitree app 里：Device → Data → Audio → Voice assistant，确认是 wake-up 模式。再在 app 的 Device → Service Status 里把 chat_go 关掉。

    为什么：只有 wake-up 模式下，机器人的麦克风才会把声音发出来，否则我们收到的是零。chat_go 是 Unitree 自带的聊天助手，不关的话有人说到它的唤醒词，它会抢着回答。

  4. 我告诉你"装好了"，并把自检结果发给你

    Claude
3

硬件自检

15 分钟
下面的命令可以我来跑，也可以你自己跑：先登录机器人，ssh unitree@<Wi-Fi 地址>，然后 cd ~/g1-greeter。测试工具要用摄像头，所以先停掉服务：systemctl --user stop g1-greeter。

  1. 完整自检，带喇叭测试

    Claude你听
    机器人上
    .venv/bin/python -m greeter --check --check-sound
    哪一项不是 PASS一般是什么原因怎么办
    api key / openaikey 没填对，或账户没充值在 platform.openai.com 检查账户余额，再告诉我
    internet路由器没信号换个位置放路由器，或者先用手机热点
    camera摄像头没插好或没被识别拔插一次 USB-C；告诉我，我来改摄像头设置
    yolo 显示 WARN每帧超过 250 ms能用，只是反应慢一点；告诉我数字
    depth 显示 WARN头部深度相机被 Unitree 自己的服务占着可以接受：程序会改用摄像头估站位区域。告诉我原文
    mic语音助手不在 wake-up 模式按 L1 + L2，再跑一次自检
    speaker没听到声音在 app 里看音量；告诉我

  2. 录 5 秒麦克风，自己听一下

    你说话

    站在机器人前面 1 米，命令开始后正常说几句话。

    机器人上
    python3 scripts/record_mic.py
    Mac 或 Ubuntu 终端，拷回来听
    scp unitree@<Wi-Fi 地址>:g1-greeter/mic_test.wav .

    应该听到：你的声音清楚，没有一直嗡嗡响。听不清的话告诉我，我们再考虑加外接麦克风。

  3. 看摄像头实时看到什么

    你走动
    机器人上
    .venv/bin/python -m greeter.robot.calibrate

    每秒打印一行：看到几个人、每个人多远、是否面朝机器人、是否站在站位区域。你分别站到 1、2、3 m 的记号上，再走进站位区域，看数字有没有跟着变。按 Ctrl + C 结束。

    应该看到：距离大致对得上记号（差几十厘米正常，第 5 段再校准）；站进站位区域时出现 spot occupied。

4

对话和新功能测试

45 分钟

  1. 启动服务，打开实时日志

    Claude
    机器人上
    systemctl --user start g1-greeter
journalctl --user -u g1-greeter -f

    日志里能看到状态变化（state idle -> noticed …）和双方说了什么（visitor: / robot:）。下面每个测试都写了该看哪一行。

  2. 让机器人站起来

    你

    用遥控器让它站起来，遥控器一直拿在手上。站稳以后再开始测。

  3. 先走一遍正常的来访

    你机器人

    日志里应该有：NOTICED track … → invitation: …（说出你身上的一件东西）→ state open -> converse → 最后 state converse -> close (goodbye)。现在默认谁都邀请，穿什么都行。

  4. 新功能逐个测（每个测完在日志里找对应的一行）

    你和同学

    🗣️一个人说个不停

    做什么
    开始聊天后，一口气说 25 秒，中间不停顿。
    应该
    大约 20 秒时机器人礼貌插话（"Sorry to jump in!"），用一句话回应，再把话头交出去。
    日志
    visitor has talked for 20 s without a break: cutting in

    ⏱️聊满一分半

    做什么
    正常一问一答，聊够 90 秒。
    应该
    它开始收尾、自己说再见，说完对话就结束，不会再多说一句。
    日志
    state converse -> close (robot said goodbye)

    👥两个人同时说话

    做什么
    你和同学一起站在站位区域，同时问两个不同的问题。
    应该
    它回答听懂的那个，再请另一个人说。听不清时请你们再说一遍。
    日志
    看 visitor: 那一行：两个人的话混在一起是正常的，只有一个麦克风。

    🎓问杜伦的具体问题

    做什么
    问它："How much are the fees for computer science?"、"How much does coursework count?"
    应该
    不报任何数字，说展台上的同事能准确回答。
    日志
    看 robot: 那一行有没有出现数字或金额。出现了一定告诉我。

    🚶边走边用（--roam）

    先改设置
    在配置文件里加 GREETER_ROAM=1，重启服务（方法见下一步）。启动日志里要有 walk detection on (rt/lowstate)。
    做什么
    一个人用遥控器带它走几步、停下；再在聊天中途带它走开。
    应该
    走的时候不邀请人，停下约 1.5 秒后恢复；聊天中走开超过 2 秒，它说一句再见就结束。
    日志
    robot is walking: no new invitations / robot is standing again / (robot walked on)。如果启动时显示 walk detection off，把那一行发我。

    🔊回声测试（--duplex，先测再开）

    先改设置
    加 GREETER_DUPLEX=1，重启服务。
    做什么
    聊天时问一个它要回答两句话的问题，它说话时你们都不出声。
    应该
    它把两句话完整说完。如果它自己说到一半停下（把自己的声音当成有人插话），就说明有回声：改回 GREETER_DUPLEX=0。没问题的话，再试一次故意在它说话时插话，它应该停下来听你说。

  5. 怎么改设置（上面两个测试要用）

    Claude或你
    机器人上
    nano ~/.config/g1-greeter/greeter.env

    在文件最后加一行，比如 GREETER_ROAM=1。按 Ctrl + O、回车保存，Ctrl + X 退出。然后重启服务：

    机器人上
    systemctl --user restart g1-greeter

    这个文件里还有 OpenAI key，别把它发给任何人，也别截图。

5

收尾：对比两个相机、校准距离、发给我

15 分钟

  1. 对比深度相机和摄像头对"站位区域有没有人"的判断

    Claude
    机器人上
    .venv/bin/python -m greeter.spot_compare recordings/$(date +%F)/trace.jsonl

    会看到：两边一致的时间占百分之几，各自单独说"有人"的时间，以及每次不一致是几点几分。测试时有人侧身站、有小个子同学站进去，最能看出区别。

  2. 校准距离（摄像头换了位置就一定要做）

    你站Claude 运行

    比如 Brio 从胸前换到头顶的弓形架上，或者换了摄像头。先停服务，你面朝机器人，按提示依次站到 1、2、3 m 的记号上，每个记号测 8 秒，屏幕上有倒计时。

    机器人上
    systemctl --user stop g1-greeter
.venv/bin/python -m greeter.robot.calibrate --stand-at 1 2 3
systemctl --user start g1-greeter

    应该看到：最后一行 GREETER_DIST_K=… saved to …。重启服务后就用新的值。

  3. 把今天的日志和结果发给我

    你
    机器人上
    journalctl --user -u g1-greeter --since today > ~/g1-greeter/today.log

    再告诉我：哪些测试正常，哪些不对，大概在几点。我会根据日志和录音调阈值（插话的秒数、走路判断、距离等）。

  4. 结束

    你

    用遥控器让机器人坐下或挂回吊架，再关机。拔下的网线收好；只要机器人要走动，就不能插着线。
