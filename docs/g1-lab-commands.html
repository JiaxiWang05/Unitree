G1 Lab Commands

Click Copy, then paste in the Ubuntu terminal with Ctrl + Shift + V. Run one block at a time. The tag on each step says where it runs: UBUNTU prompt is your laptop user, e.g. you@laptop, ROBOT prompt is unitree@ubuntu.

Robot login password: the robot computer's unitree user (ask the lab; it is not the Unitree app account). When it asks ros:foxy(1) noetic(2) ? type 1. The robot stays hanging; nothing here makes it move.

1. Log in to the robot

UBUNTU 
ssh unitree@192.168.123.164

2. Backup on the robot

ROBOT 
sudo tar czf /tmp/g1-etc.tgz /etc 2>/dev/null; dpkg -l > /tmp/g1-packages.txt; pip3 list > /tmp/g1-pip.txt 2>/dev/null
tar czf /tmp/g1-home.tgz -C ~ . 2>/dev/null; ls -lh /tmp/g1-*

The second block takes a minute or two. You should see 4 files: g1-etc.tgz, g1-home.tgz, g1-packages.txt, g1-pip.txt.

3. Camera test on the robot

ROBOT 
ls /dev/v4l/by-id/
python3 - <<'EOF'
import cv2, glob
for p in sorted(glob.glob('/dev/v4l/by-id/*index0')):
    c = cv2.VideoCapture(p); ok, f = c.read(); c.release()
    print(p, 'OK %dx%d' % (f.shape[1], f.shape[0]) if ok else 'no frame')
    if ok: cv2.imwrite('/tmp/' + p.split('/')[-1] + '.jpg', f)
EOF

Look for a line with Trust and OK 640x480 (or similar). RealSense lines are the head depth camera. Then leave the robot:

exit

5. Microphone test

  • On the remote press L1 + L2 together (wake-up mode). Without it the mic sends only zeros.
  • In the Unitree app: Device → Service Status → switch off chat_go.
UBUNTU 
cd ~ && git clone https://github.com/JiaxiWang05/Unitree.git; scp ~/Unitree/scripts/record_mic.py unitree@192.168.123.164:~

Stand 1 m in front of the robot. Run this, then talk normally for 5 seconds:

ssh unitree@192.168.123.164 'python3 record_mic.py'
scp unitree@192.168.123.164:mic_test.wav ~/g1-backup/ && aplay ~/g1-backup/mic_test.wav

Good: your voice is clear, no constant hum. No audio or All zeros: press L1 + L2 again and record again.

6. Log in without a password from now on

UBUNTU 
ls ~/.ssh/id_* 2>/dev/null || ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519; ssh-copy-id unitree@192.168.123.164

Asks for the robot password once. Test: ssh unitree@192.168.123.164 hostname should print a name without asking for a password.

7. Internet for the robot through Ubuntu

Ubuntu shares its Wi-Fi with the robot over the cable (the laptop's Wi-Fi must be its default route; the wired port has no gateway). Asks for the Ubuntu password. It all resets when either machine reboots.

UBUNTU 
sudo sysctl -w net.ipv4.ip_forward=1 && sudo iptables -t nat -A POSTROUTING -s 192.168.123.164 -o $(ip route | awk '/^default/ {print $5; exit}') -j MASQUERADE && sudo iptables -I FORWARD -s 192.168.123.164 -j ACCEPT && sudo iptables -I FORWARD -d 192.168.123.164 -j ACCEPT
ssh -t unitree@192.168.123.164 'sudo ip route add default via 192.168.123.99; date; ping -c 2 8.8.8.8 && ping -c 2 google.com'

The robot password again, for sudo. Both pings should answer. If 8.8.8.8 answers but google.com fails, run this, then ping again:

ssh -t unitree@192.168.123.164 'echo nameserver 8.8.8.8 | sudo tee /etc/resolv.conf'
